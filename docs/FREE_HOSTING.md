# Free live hosting — Render + Neon

The repository includes a single Docker app that serves the React website and Python API together. The Render blueprint selects **Free**. Use a **Free** Neon database for persistent accounts and tickets. No paid plan is configured.

## 1. Create the free database

1. Open https://console.neon.tech and sign up/sign in, using GitHub if offered.
2. Choose the **Free** plan and create a project named `schemesathi`. Select the nearest available region.
3. Open **Connect** and copy a **direct/unpooled PostgreSQL connection string**. It starts with `postgresql://` and includes the password and SSL parameters.
4. Keep it private. Do not put it in GitHub, a screenshot or this chat. The backend accepts that connection string and converts it to its async driver automatically.

## 2. Create the free web service

1. Open https://dashboard.render.com and sign up/sign in.
2. Connect your GitHub account **prashasti2772** and allow access to the **SchemeSaathi-AI** repository.
3. Choose **New → Blueprint**, select that repository and the **main** branch. Render reads `render.yaml`.
4. Confirm the web service is **Free** and that no paid disk/database is selected. If the site offers only paid choices, stop and check the account/region requirements.
5. Enter the environment values below, then create/deploy the blueprint.

| Variable | What to enter |
|---|---|
| DATABASE_URL | The private Neon connection string from step 1 |
| PUBLIC_SITE_URL | Initially `https://schemesathi-ai.onrender.com`; correct it to the actual URL Render assigns |
| JWT_SECRET_KEY | Generated by the blueprint; do not replace with the example/default secret |
| CORS_ORIGINS | `[]` is suitable when the website and API are served together by this Docker image |

After the build succeeds, open the assigned HTTPS URL. Update `PUBLIC_SITE_URL` if it differs. Render redeploys new commits to main when automatic deployment is enabled.

## 3. Verify the public prototype

- Open `https://YOUR-APP.onrender.com/health`; it should return status `ok`.
- Register a test account, then sign in.
- Complete the wizard and check that scheme cards display.
- Ask the chatbot about a business loan.
- Open Support, create a ticket, refresh, and confirm it persists.
- Check the email and phone contact links.
- Check voice status. Browser voice works only where the browser supports it. Bhashini stays disabled until its credentials are configured.

Cold starts on a sleeping free service can take time. If the first request times out, allow the health page to load and retry.

## 4. Enable the optional services

In Render **Environment**, add Bhashini credentials or MSG91 credentials from your own provider account, then redeploy. See the root README for exact keys and the approved SMS template configuration. Hosting being free does not make third-party SMS delivery free.

- **Bhashini:** `BHASHINI_USER_ID`, `BHASHINI_API_KEY`, and the account-authorized `BHASHINI_PIPELINE_ID`.
- **SMS:** `MSG91_AUTH_KEY` and approved `MSG91_SENDER_ID`; a reset SMS Flow ID in `MSG91_OTP_TEMPLATE_ID` with the `otp` variable; a separate outreach Flow ID in `MSG91_TEMPLATE_ID` with the `website` variable. The separate MSG91 **OTP Templates** screen is not the SMS Flow setup used by this project. Keep `SMS_LIVE_ENABLED=false` until outreach is ready; recovery SMS uses its own configuration.
- **Recovery email:** `EMAIL_PROVIDER=resend`, `RESEND_API_KEY`, and `EMAIL_FROM_ADDRESS` on a domain you own and have verified in Resend. Gmail SMTP cannot work on Render Free: it [blocks outbound ports 25, 465 and 587](https://render.com/docs/free). Resend's test sender can mail only the account owner; other recipients require a [verified sending domain](https://resend.com/docs/knowledge-base/403-error-resend-dev-domain). Domain ownership is a separate prerequisite, not included with the free Render URL.

Use [provider setup](PROVIDER_SETUP.md) for draft SMS texts and required approvals, and [password recovery setup](PASSWORD_RECOVERY.md) for email/SMS configuration. Local `.env` changes do not update Render automatically: enter the corresponding settings in its Environment screen. Do not share secret values in chat.

For a staff helpdesk account, run the local `scripts/create_staff.py` command from `apps/backend` with the **same Neon DATABASE_URL** configured in your private local backend `.env`. The script prompts for a password, creates a staff account, and does not print it. Sign in to the deployed site and open Support.

## Limits and costs

- Render Free web services have inactivity/usage limits and no persistent local disk.
- Neon Free has its own storage/compute limits. Stay on Free and do not enable a paid plan to follow this guide.
- Render's own free PostgreSQL instance expires after 30 days; this guide uses Neon instead.
- Real Bhashini and MSG91 calls require access granted by those providers. No real messages were sent during the repair.
- Provider sign-in, verification or service availability can require your direct action. The local repaired prototype remains usable even before hosting.

Official references: [Render Free](https://render.com/docs/free), [Render first deploy](https://render.com/docs/your-first-deploy), [Neon Free plan](https://neon.com/pricing).
